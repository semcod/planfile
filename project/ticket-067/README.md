## Goal and scope

`goal -a` refused to deliver in this repository with `GOV-MANIFEST-001`: only the
publication-policy note from 0.20.10 was adopted, while the governance package
itself (`.governance/governance_check.py`, `manifest.json`,
`manifest.lock.json`, `stack-profiles.json`) was missing.

Two blockers were fixed:

1. `.gitignore` hid the managed adoption targets. A blanket `.github/` ignore
   cannot be undone by a negation, so it is removed (the three files already
   tracked there are unaffected); `.aider*` keeps ignoring scratch files but
   lets `.aider.conf.yml` through.
2. `AGENTS.md` differed from the managed file and needed `--upgrade`. The
   inline `wellmanifest:local-ci-publication` block from 0.20.10 is superseded:
   rule 11a of the adopted `AGENTS.md` points at
   `.governance/docs/LOCAL_CI_PUBLICATION.md`, which this adoption installs, so
   the local OneDev + independent Validator route is preserved.

Adoption is pinned to the published release 0.20.25,
`d54878a105a20d84dd554f205bc177dcacc8730a`. `project/TICKETS.md` (a required
file that was missing) is generated by the managed `project/readme.sh`, and
`scripts/install-agent-hosts.sh` activates `core.hooksPath=.githooks`.

Because the bootstrap necessarily writes shared contract paths
(`.governance/manifest.json`, `required-checks.json`, `ticket-allocation.json`,
`AGENTS.md`, `pyproject.toml`), the ticket runs in the `integration`
workstream. Three changed paths had no owner in the pinned registry and are
added to that workstream's `ownedPaths`:

- `.gitignore` — the adoption refuses to run while the managed targets are ignored;
- `docker-compose*.yml` — the registry only matched `compose*.yml`, so the digest
  pinning that `GOV-DOCKER-002` demands had no owner;
- `project.bat` — an optional seed alias that exists in this repository only
  because the bootstrap creates it (it is not part of the verified managed
  payload, so the atomic adoption proof does not cover it).

Out of scope: any source, test or packaging change, a release, and the PyPI
publish that `goal -a` will be able to run once this lands.
